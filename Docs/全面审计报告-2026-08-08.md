## 一、P0 严重（数据正确性 / 隐私模型违约）

### P0-1 音频离线缓存按裸 trackID 命名，跨服务器串库（错曲离线播放）
- 位置：`OfflineManager/TrackCacheStore.swift:10,29,44-45,54-55,64`；`AppShell/AuralisAppModel.swift:97,1041,1407,1451`
- 证据：磁盘文件名 / `index.json` 键 / `downloadedTrackIDs: Set<TrackID>` 全部用裸 `trackID`，不含 `serverID`。
- 影响：两台服务器存在同 ID 曲目（泛 Subsonic 数字 ID 常见）时：① B 服务器同 ID 曲目被误判“已下载”，拒绝下载；② **离线播放用 A 的音频文件播 B 的曲目（错曲）**；③ `removeDownload`/清理会误删另一台服务器的离线文件。与验收清单「两台服务器数据隔离」直接冲突。
- 建议：缓存键/文件名/`downloadedTrackIDs` 全部改为 `GlobalID(serverID|trackID)`，文件名加 server 前缀或哈希，迁移旧索引。

### P0-2 歌词磁盘缓存（含负缓存）按裸 trackID 键，跨服务器串库 + 负缓存永久误伤
- 位置：`LyricsKit/LyricsDiskCache.swift:16,34-68,105-108`；`AuralisAppModel.swift:1758,1764,1773,1776`
- 证据：歌词文件名与 `misses`（无歌词负缓存）集合都以 `trackID.rawValue` 为键；切服务器只清内存不清磁盘。
- 影响：B 服务器同 ID 曲目读到 A 的歌词；更严重的是——A 服务器确认“无歌词”后，B 服务器同 ID 曲目**永远不再请求歌词**（负缓存命中，不可自愈）。
- 建议：键并入 serverID；`purgeServer` 时清理该服务器歌词文件与 misses。

### P0-3 AI 隐私开关是装饰：关闭后仍发送歌曲元数据/播放历史，且无「请求前权限展示」
- 位置：`SettingsView.swift:139-141`、`MacSettingsWindow.swift:149-151`（开关 UI）；`AgentCoordinator.swift:262-294`、`AgentRunner.swift:788-806`（发送逻辑）；`AIKit/AIProvider.swift:246-253`（`AIPrivacyPermissions` 定义）
- 证据：`auralis.ai.allowsMetadata/allowsLyrics/allowsHistory` 三个 `@AppStorage` **全仓无任何读取方**（已 grep 验证）；`AIPrivacyPermissions` 结构体零引用。`AgentCoordinator.startRun` 无条件把当前歌曲、最近 5 首播放、服务器名、目录计数写进上下文并拼进 systemPrompt。
- 影响：用户在设置里关闭三个隐私开关后，AI 助手仍把歌曲元数据、播放历史、服务器名发给第三方大模型，直接违反 `PrivacyModel.md`「默认拒绝」与「每次请求前展示字段列表…用户可取消」承诺。
- 建议：三个开关接入真实 gating（关元数据→不发 trackLine；关历史→不发 recentLine；关歌词→不发歌词内容）；首轮外发前增加一次性字段/Provider/模型/Token 估算确认。
