# 苹果端触感与 AI 助手审查、修复记录

基线：`d3003b412190bb68a944be486f9c0996b25b9255`（main）。
分支：`codex/apple-haptics-agent-learning`。

本轮检查重点是 AVFoundation 播放与 PCM 旁路、MusicHaptics 分析/混音/输出，以及 Agent 的请求语义、工具选择、记忆召回和本地技能持久化。修改只涉及苹果端 Swift 模块、测试及本文档。

## 发现与修改

| 问题 | 原因与影响 | 修改 |
| --- | --- | --- |
| 纹理曲线干扰鼓点 | 同一个 CHHapticPattern 中的动态控制会影响所有正在播放和后续事件，持续低音曲线也会缩放鼓点 | 将无曲线事件与纹理拆成独立 pattern；重叠纹理分配不同层，连续、不重叠的纹理复用同层 |
| 纹理强度被重复缩放 | 静态 intensity 已乘用户强度，绝对曲线又乘强度后作为动态乘数；sharpness 的绝对值还会叠加静态值 | 带曲线纹理使用 intensity=1、sharpness=0 的基值，只在曲线应用一次用户强度 |
| 未来触感被提前中断 | 旧实现只按 player 数量淘汰最早创建的第 9 个 player，未检查其是否已结束 | 按 Core Haptics 时钟回收已结束窗口；保留进行中事件，突发负载达到 32 个 player 时丢弃新触感片段，优先播放流畅 |
| 跨层 seek/resume 不完整 | 多层时不能只恢复最后一个 player；部分层可能已在 seek 目标前结束 | 所有层从同一个歌曲位置重新裁剪未来事件，用共同引擎时刻启动 |
| 普通拍经常被当成强拍 | RMS 音量与包含频谱/对数起音成分的检测阈值直接比较，尺度不一致 | 按最近 16 次起音的音量中位数判定相对重音；稳定等响节拍保持普通拍 |
| 低功耗时节奏适应滞后 | 跳过 2/4 倍 FFT 帧后仍按单帧 hop 更新包络，历史样本数也未缩短 | 按实际音频时间更新包络，并按分析步长调整历史容量；复用每帧 dB 排序结果 |
| 中文旧记忆漏召回 | 系统提示词把整句无空格中文当一个词；memory_search 只做完整子串匹配 | 共用中文相邻字对与拉丁词召回，按相关性排序，处理大小写、全角及重音字符；移除 AppShell 中旧的子串检索覆盖实现 |
| 相关技能被新技能挤出 | 只注入最近 8 个技能 | 根据当前目标匹配技能名称和完整指令，再按时间排序；保持原有注入条数上限 |
| 工具依赖被二次裁剪 | 歌曲/歌单解析工具虽被加入候选列表，却因没有字面相关分数被 Top-K 去掉 | 保留实际入选工具需要的 TrackID/PlaylistID 解析入口，不受 filler 配额影响 |
| 连续自然语言续做丢失原任务 | 短续写词表不包括英文 continue、繁体及部分常见中文说法 | 扩充明确续做表达；多次续做仍回溯原请求，新独立请求不继承旧任务 |
| 记忆保存失败却污染后续上下文 | 先修改内存，再写磁盘；失败未回滚 | save/delete/clear 写入失败时恢复旧内存，后续召回不会把未保存信息当成已记住 |

触感算法版本升级为 `auralis-haptics-v2.5`，旧缓存会重新分析。PCM 渲染回调未增加处理、锁或等待。AI 没有新增权限、确认流程或隐私开关。

## 经验复用的实际边界

原有 skill_create 已支持同名更新及跨会话保存。本轮使相关旧技能能进入当前上下文，并补充读取旧步骤、整合用户纠正、保存成功流程、下次复用的提示。它属于运行时的记忆和技能复用，不是修改模型权重，也不能保证模型自动学会所有新任务。memory_search 属于确定性词法召回，不是语义向量模型。

## 真机验收

1. 同一首熟悉歌曲对比触感开/关，包含流媒体、离线、蓝牙耳机；音乐不能新增卡顿。
2. 选择同时有低音持续纹理和鼓点的段落，比较鼓点清晰度与强弱，不应因纹理衰减而一起变弱。
3. 切换轻/中/强，检查纹理平滑增强；等响规律节拍不应拍拍都变成重击。
4. 在持续纹理中暂停、拖动、恢复，检查所有层同步；再测试 0.5×/1×/2×。
5. 开启低功耗模式后测试节奏变化，检查是否仍能及时跟随；静音/静默片段不应补出固定节拍。
6. 聊天测试：先找到 51 首歌，再说“把这些歌创建为夜跑歌单”；核对服务器真实歌单数量。失败时继续检查工具加载/返回，而非把本轮 shortlist 修复视为整条链路已获真机验证。
7. 聊天测试：让助手保存并纠正夜跑选曲流程，另建多个无关技能后开启新会话，询问“帮我找适合夜跑的周杰伦歌曲”；检查相关记忆、skill_read 和最终工具结果。

## Apple Music 对标依据

目标是音频同步的敲击、纹理与细腻变化，不能宣称本轮已经复刻 Apple Music 的触感效果或专有算法。现有系统 Music Haptics 匹配路径继续保留。

- [Apple：Core Haptics 的事件与动态控制](https://developer.apple.com/videos/play/wwdc2019/223/)：动态参数作用于整个 pattern 中正在播放和后续事件。
- [Apple：hapticIntensityControl](https://developer.apple.com/documentation/corehaptics/chhapticdynamicparameter/id/hapticintensitycontrol)
- [Apple：hapticSharpnessControl](https://developer.apple.com/documentation/corehaptics/chhapticdynamicparameter/id/hapticsharpnesscontrol)

真机音频流畅度、触感延迟和主观效果仍需上述验收；本轮不报告未经测量的毫秒数或性能提升百分比。
