# 设置中的后台标签分类

标签分类直接调用设置中的模型，将固定标签写入本地索引。任务由应用持有，与助手会话、聊天工具循环及页面生命周期分开。

## 入口与操作

- iOS：设置 → 标签分类。
- macOS：设置 → 资料库与播放 → 标签分类。
- Android 手机 / TV：设置 → 标签分类卡片；曲库中的管理入口也指向设置。

先在大模型设置中配置模型，并保持 AI 与歌曲元数据权限开启。在标签分类中确认“允许发送歌曲元数据进行分类”，然后点击开始/继续。分类授权独立于聊天的首次外发确认；不需要打开助手、建立会话或让模型调用工具。

设置显示当前音乐库已处理、待处理数量、运行状态和错误。暂停只停止未提交的请求，已提交批次保存在 SQLite / Room；继续时重新查询待处理曲目。聊天的停止按钮不影响分类。模型认证、网络、协议错误会显示在设置中，不会把失败批次标记成已完成。

如果模型没有足够证据而返回空标签，界面会显示未获得标签的数量。“重试无标签曲目”只将这些记录重新排入任务，不影响已有标签，避免“已处理”被误解成“每首都有可用分类”，也无需清空整个索引。

现有有效分类保留，不强制重跑。清空索引和索引包导入/导出仍使用已有设置中的备份操作，不自动删除数据。

## 后台执行

Android 使用进程级任务与 `dataSync` 前台服务，通知显示进度并提供暂停操作。离开设置、切换页面和 Activity 重建不会取消任务。系统限制前台服务时停止运行并保留已完成数据；应用进程被终止后，可以重新打开设置继续。

macOS 使用应用持有的任务并避免 App Nap 中断正在进行的工作。退出应用后任务停止，重新打开后可继续。

iOS 注册 `BGProcessingTask`，需要网络连接，结合系统允许的后台处理时间与短期后台执行。系统何时调度、允许运行多久由 iOS 决定；不能承诺持续常驻。手动暂停会取消尚未执行的后台请求，系统到期会停止当前请求并保留待继续的处理意图。已完成的批次不受系统中断影响。

## 分类与写入链路

1. 校验目标音乐库、AI 开关、歌曲元数据权限和专门的分类授权。
2. 从本地目录读取待处理歌曲，按输出预算选择小批次，默认上限 8 首。
3. 只发送歌曲内容元数据与固定标签目录；不发送聊天、歌词、播放历史、收藏、评分、文件路径、流媒体地址或凭据。
4. 模型返回 JSON；拒绝工具调用、外来 ID、重复 ID 和不完整批次。结构不完整时有限缩批重试，到单首仍失败则显示错误。
5. 再次检查授权、目标音乐库和取消状态。
6. 在原子写入边界核对请求时的内容指纹。歌曲在分类期间改名或改变其它内容元数据时拒绝旧响应，不将旧标签盖成最新分类。
7. 写入成功后读取真实数据库状态，再处理下一批。无证据的标签可省略，不强行猜测；索引处理完成不等于模型对每首歌曲都有足够证据给出标签。

分类结果沿用固定标签、同义词归一、多标签推荐及撞库回退路径。后台任务本身不播放歌曲或修改歌单。

## 验证

新增用例覆盖文本模型无需工具调用的完整分类链路、批次缩小、暂停后只处理剩余曲目、取消后的迟到响应、授权撤销和元数据变化。Android 使用本地模拟 HTTP 服务验证真实 Provider 编解码、响应解析与 Room 写入；同时验证标签可被推荐索引消费。

Linux 可运行 Android 测试与 Swift 语法检查。Apple 数据库与应用集成以原生 CI 为准；系统后台调度时间、通知交互和真实模型的效果仍需设备验证。没有用户的模型凭据或设备曲库，模拟 HTTP 成功不能代表所有实际模型配置都已经实测。
