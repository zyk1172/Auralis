# Security policy

Please do not report a security vulnerability in a public issue. Use GitHub’s private
“Report a vulnerability” / Security Advisory flow for this repository when it is available. If
that flow is not available, contact the repository owner through a private channel listed on the
owner’s GitHub profile and include “Auralis security report” in the subject.

Include, if safe to share privately:

- affected commit, release, platform, and configuration;
- a concise impact description and reproducible steps or a minimal proof of concept;
- logs with credentials, cookies, personal data, authenticated URLs, and private network details
  removed;
- whether the issue involves a dependency and the relevant package/version.

Never paste API keys, bearer tokens, passwords, signing keys, provisioning profiles, user library
data, or private server addresses into a public issue, pull request, or chat transcript. If a
credential may have been exposed, revoke or rotate it with its provider immediately and mention
the credential class privately without disclosing the value.

Dependency vulnerabilities should include the dependency name, exact version, affected target,
and the upstream advisory when known. This policy concerns release and software security; it does
not add restrictions to the capabilities of the AI Assistant.
